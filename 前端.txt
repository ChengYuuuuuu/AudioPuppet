第一步：构建产物准备
bash
npm run build
构建完成后，你的 dist/ 目录应包含：

assets/（前端代码 + 静态资源）

index.html

不包含 models/（模型不能放静态托管）

第二步：模型文件拆出，上传到 Cloudflare R2
需要上传的文件：

文件	大小	说明
sofa_mandarin_simplified.onnx	406 MB	必须放 R2
htdemucs_ft_vocals_safe16.onnx	84 MB	建议放 R2（Pages 单文件限制 25MB）
R2 配置步骤：

登录 Cloudflare 控制台 → R2 → 创建存储桶（如 my-app-models）

上传两个 ONNX 文件

设置存储桶为 公开访问

配置 CORS：

json
{
  "AllowedOrigins": ["*"],
  "AllowedMethods": ["GET"],
  "AllowedHeaders": ["*"]
}
记录文件公网 URL：

https://my-app-models.r2.dev/sofa_mandarin_simplified.onnx

https://my-app-models.r2.dev/htdemucs_ft_vocals_safe16.onnx

WASM 文件（≤27MB）：

不需要上传 R2

onnxruntime-web 默认从 CDN（jsdelivr）加载

也可配置 ort.env.wasm.wasmPaths 指向静态托管

第三步：前端代码修改
onnxLoader.ts 中修改模型路径：

typescript
// 原来
const modelPath = '/models/sofa_mandarin_simplified.onnx';

// 改成
const modelPath = 'https://my-app-models.r2.dev/sofa_mandarin_simplified.onnx';
同理修改 Demucs 模型路径（demucs.ts 或 processor.js）。
建议使用环境变量（Vite 的 import.meta.env），避免硬编码。

第四步：静态托管部署
方式一：GitHub Pages

bash
npx gh-pages -d dist
访问：https://<用户名>.github.io/<仓库名>/

方式二：Cloudflare Pages

连接 GitHub 仓库

构建命令：npm run build

输出目录：dist

注意：前端代码请求模型的 URL 必须指向 R2，而非静态托管。

第五步：清理调试代码
删除或注释 POST /log-alignment 上报逻辑（sofaPipeline.ts）

确认 vocalSeparation 状态正常透传到 processChunk

第六步：验证
打开部署后的网页

输入歌曲 ID，点击分析

打开 DevTools → Network 面板：

模型从 R2 加载（r2.dev）

WASM 从 CDN 加载

前端代码从静态托管加载

资源存放总览
资源	存放位置	说明
前端代码	GitHub / Cloudflare Pages	dist/ 目录
WASM 文件	CDN	onnxruntime-web 默认加载
模型文件	Cloudflare R2	公开读取 + CORS 配置
歌曲信息	meting API（第三方）	在线解析
